# Исследование: Rolling Seasonality Ridge

## Предпосылки (Problem Statement)

### Текущая проблема
Базовая модель `Ridge` использует **глобальную сезонную норму**, вычисленную на всей истории (кроме выбросных лет 2022, 2010):

```python
# Текущий подход в Ridge
seasonal_norm = clean_df.groupby('month')['MoM'].mean()
```

**Проблема:** После структурных сдвигов 2022-2024 годов исторические паттерны сезонности перестали работать. Модель "помнит" старые паттерны (2010-2021), которые больше не актуальны.

### Эмпирические наблюдения
Из `docs/BACKTEST_METHODOLOGY.md`:
- **Huber** (MAE 0.289) лучше Ridge — потому что робастна к выбросам и не полагается на сезонность
- **Ridge Shock** (MAE 0.299) улучшает Ridge за счёт дамми для шоковых периодов
- **SubcomponentMulti** (MAE 0.265) лучшая модель — использует оптимальные модели по компонентам

**Гипотеза:** Сезонность должна адаптироваться к "новой реальности". Если использовать только последние 24-36 месяцев для расчёта сезонности, модель будет более адекватной.

---

## Предлагаемое решение

### Rolling Seasonality Ridge

Вместо глобальной сезонной нормы — **скользящая сезонность**:

```python
# Новый подход: сезонность на последних N месяцев
seasonal_norm = df.last(f'{self.seasonality_window}M').groupby('month')['MoM'].mean()
```

**Параметры для тестирования:**
- `seasonality_window=24` — последние 2 года
- `seasonality_window=36` — последние 3 года
- `seasonality_window=48` — последние 4 года (для сравнения)

### Почему это может сработать

1. **Адаптация к новой реальности:** После 2022 года экономика вошла в новый режим (высокая волатильность, санкции, импортозамещение). Сезонность 2010-2021 может вредить.

2. **Устойчивость к структурным сдвигам:** Если в 2024-2025 снова произойдут изменения, rolling window быстрее адаптируется.

3. **Сохранение преимуществ Ridge:** Лаговые признаки, макро-признаки (Ki, Ruonia), регуляризация — всё остаётся.

---

## Методология тестирования

### Бэктесты
Проводим стандартные бэктесты согласно `docs/BACKTEST_METHODOLOGY.md`:

1. **h=1** (главный КПЭ): Rolling window за последние 12 месяцев
2. **h=2**: Rolling window, прогноз второго месяца
3. **h=12**: Фиксированный cutoff (ноябрь 2024)

### Метрики
- **MAE** — главная метрика
- **RMSE** — для оценки волатильности ошибок
- **KPI Violations** — количество месяцев с |error| > 0.5
- **Coverage 50%** — % точек в диапазоне ±0.5

### Сравнение с baseline
- **Ridge** (MAE 0.310) — текущий baseline
- **Huber** (MAE 0.289) — лучшая production модель
- **SubcomponentMulti** (MAE 0.265) — лучшая экспериментальная

---

## Ожидаемые результаты

### Оптимистичный сценарий
- MAE h=1: 0.28-0.29 (улучшение vs Ridge 0.310)
- Близко к Huber (0.289) или лучше
- Улучшение на h=12 за счёт адаптивной сезонности

### Реалистичный сценарий
- MAE h=1: 0.30-0.32 (сопоставимо с Ridge)
- Небольшое улучшение на h=12
- Потеря стабильности на очень коротких выборках (< 24 месяцев)

### Пессимистичный сценарий
- MAE h=1: > 0.32 (хуже Ridge)
- Rolling window слишком "шумная"
- Не хватает исторических данных для стабильной сезонности

---

## Риски

1. **Недостаточно данных:** При window=24 месяца каждая точка сезонности — среднее всего 2 значений. Высокий шум.

2. **Лаг адаптации:** Если сезонность меняется резко, rolling window будет "тянуть" старые паттерны.

3. **Переобучение:** Слишком маленькое окно может привести к переобучению на последних данных.
