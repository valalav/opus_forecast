# Методика бэктестинга модели СИРЕНА-КБР

## Общее описание

**Бэктестинг (backtesting)** — это метод валидации прогнозной модели на исторических данных, при котором мы имитируем реальный процесс прогнозирования: на каждую дату прогноза модель обучается только на данных, которые были бы доступны на тот момент.

---

## Схема скользящего бэктеста (Rolling Window Backtest)

```
Временная шкала данных:
|-------- История --------|-- Прогноз --|
2010-01                   T-1           T

Для каждой целевой даты T:
1. Берём все данные до T-1 (включительно)
2. Обучаем модель на этих данных
3. Делаем прогноз на дату T
4. Сравниваем с фактом
5. Сдвигаем T на 1 месяц вперёд
6. Повторяем
```

### Пример скользящего окна

```
Итерация 1: Прогноз на январь 2019
├── Обучение: 2010-01 ... 2018-12 (все данные до декабря 2018)
├── Прогноз:  2019-01
└── Сравнение с фактом января 2019

Итерация 2: Прогноз на февраль 2019
├── Обучение: 2010-01 ... 2019-01 (добавился январь 2019)
├── Прогноз:  2019-02
└── Сравнение с фактом февраля 2019

Итерация 3: Прогноз на март 2019
├── Обучение: 2010-01 ... 2019-02 (добавился февраль 2019)
├── Прогноз:  2019-03
└── Сравнение с фактом марта 2019

... и так далее до последней даты с известным фактом
```

---

## Ключевые принципы

### 1. Отсутствие утечки данных (No Data Leakage)

**Критически важно:** при прогнозе на дату T модель НЕ должна видеть:
- Факт на дату T
- Любые данные после T-1
- Информацию, которая не была бы доступна в реальности

```python
# ПРАВИЛЬНО: обучение на данных до cutoff
cutoff = target_date - pd.DateOffset(months=1)
train_df = df[df.index <= cutoff]

# НЕПРАВИЛЬНО: утечка данных
train_df = df[df.index <= target_date]  # Включает факт target_date!
```

### 2. Динамический пересчёт сезонной нормы

Сезонная норма (среднее по месяцам) должна пересчитываться на каждой итерации, используя только доступные данные:

```python
# На каждой итерации бэктеста:
train_clean = train_df[~train_df['year'].isin(OUTLIER_YEARS)]
seasonal_norm = train_clean.groupby('month')['ИПЦ'].mean()
```

### 3. Горизонт прогнозирования

В нашей модели используется горизонт **H=1 месяц** (nowcasting):
- Прогноз делается на следующий месяц после последних известных данных
- Это соответствует реальному сценарию: в конце месяца T-1 прогнозируем инфляцию месяца T

## Параметры бэктеста

### Период тестирования

```python
# Автоматическое определение периода
last_date = df.dropna(subset=['Все товары и услуги']).index.max()

# Начало бэктеста: минимум 3 года истории для обучения
start_date = max(df.index.min() + pd.DateOffset(years=3), 
                 pd.Timestamp('2019-01-01'))

# Конец бэктеста: последняя дата с фактом
end_date = last_date
```

### Минимальное окно обучения

```python
MIN_TRAIN_SIZE = 36  # месяцев (3 года)

# Пропускаем итерацию, если недостаточно данных
if len(train_df) < MIN_TRAIN_SIZE:
    continue
```

## Метрики качества

### MAE (Mean Absolute Error)
```
MAE = (1/N) × Σ|факт_i - прогноз_i|
```
Средняя абсолютная ошибка в процентных пунктах.

### КПЭ (Ключевой Показатель Эффективности)
```
КПЭ = доля прогнозов с |ошибка| ≤ 0.5 п.п.
```
Целевой КПЭ: ≥75% прогнозов попадают в коридор ±0.5 п.п.

### RMSE (Root Mean Square Error)
```
RMSE = √[(1/N) × Σ(факт_i - прогноз_i)²]
```
Корень из среднего квадрата ошибок, штрафует большие промахи.

## Псевдокод бэктеста

```python
def backtest(df, model):
    """
    Скользящий бэктест модели.
    
    Args:
        df: DataFrame с данными (индекс = даты)
        model: модель с методами fit() и predict()
    
    Returns:
        DataFrame с результатами бэктеста
    """
    # Автоматическое определение периода
    last_fact_date = df.dropna(subset=['Все товары и услуги']).index.max()
    
    # Генерируем даты для тестирования
    test_dates = pd.date_range(
        start='2019-01-01',  # или автоматически от MIN_TRAIN_SIZE
        end=last_fact_date,
        freq='MS'  # Monthly Start
    )
    
    results = []
    
    for target_date in test_dates:
        # 1. Определяем cutoff (данные до target_date)
        cutoff = target_date - pd.DateOffset(months=1)
        
        # 2. Формируем обучающую выборку
        train_df = df[df.index <= cutoff]
        
        # 3. Проверяем достаточность данных
        if len(train_df) < MIN_TRAIN_SIZE:
            continue
        
        # 4. Обучаем модель
        model.fit(train_df)
        
        # 5. Делаем прогноз
        prediction = model.predict(target_date)
        
        # 6. Получаем факт
        actual = df.loc[target_date, 'Все товары и услуги']
        
        # 7. Сохраняем результат
        results.append({
            'date': target_date,
            'actual': actual,
            'prediction': prediction,
            'error': actual - prediction
        })
    
    return pd.DataFrame(results)
```

## Важные замечания

### Что НЕ является утечкой данных:

1. **Использование лагов** — `y_lag1 = y.shift(1)` на момент T содержит значение T-1, которое уже известно
2. **Сезонная норма** — если она вычисляется только по данным до cutoff
3. **Гиперпараметры** — если они выбраны на отдельном валидационном наборе или через кросс-валидацию

### Что ЯВЛЯЕТСЯ утечкой данных:

1. Использование факта целевой даты в признаках
2. Вычисление статистик по всему ряду (включая будущее)
3. Выбор признаков на основе корреляции с будущими данными
