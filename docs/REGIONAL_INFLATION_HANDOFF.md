# Передача задачи: автономный региональный прогноз инфляции

Обновлено: **2026-09-28**. Состояние реализации зафиксировано в коммите **33a5bfd**.
Документ предназначен для агента, продолжающего работу без истории переписки.

## Цель пользователя и контекст

Разработать отдельный инструмент для коллег: выбрать регион России, загрузить актуальную
статистику, получить Ridge/Huber-прогноз инфляции и проверить его на прошлых периодах.
Работа должна быть возможна автономно на Windows без установки Python и тяжёлых пакетов.
Пользователь согласовал начало с HTML; вычислительное ядро реализовано на Rust/WASM.
Нужны изменяемые в интерфейсе параметры, разумные исходные настройки, сохранение данных
для работы без интернета и ZIP для передачи коллегам.

Предпочтение пользователя: максимально поручать ограниченные задачи **Luna**, но проверять
результаты и принимать окончательные модельные решения основному агенту.

Задача выросла из обновления прогноза ОПР10.2026 до конца 2027 года: сентябрьский nowcast,
октябрьская индексация тарифов примерно на 10%, перенос издержек, топливо, плодоовощная
сезонность и сравнение с **ОПР09.2026**. Не путать прошлый ОПР с датой имени Excel-формы.
Текущий этап — региональное приложение и тарифные эксперименты, **не пересмотр отправочной
траектории ОПР**. Контекст отправочного прогноза: [отчёт ОПР10](../archive/results/opr102026_adjusted_20260928/REPORT.md).

## Что уже реализовано

- Выбор из 101 территории в пакете данных; это не 101 субъект РФ. RAW и SA, Ridge и Huber.
- Локальный поиск статистики рядом с приложением по умолчанию, отдельный путь/выбор папки,
  загрузка из Яндекс Диска, импорт и сохранение пакетов.
- Официальные Ki и RUONIA с сайта Банка России, импорт/экспорт для офлайн-работы.
  Исходные XML, агрегированные значения и сведения об источнике сохранены.
- Прогноз, график и CSV с месячными и составными годовыми темпами RAW.
  Для SA официальный годовой темп не выводится.
- Скользящие бэктесты h=1/2/12, MAE/RMSE/смещение/доля ошибок в пределах 0,5 п.п.,
  явное число валидных прогнозов и причины недоступности.
- Настройки сезонности, исключённых лет, Ridge/Huber и MAD-ограничения выбросов;
  сравнение с ограничением и без него на совпадающих наблюдениях.
- Ручной будущий тарифный сценарий: месяц, индексация, вес в общем ИПЦ,
  предполагаемый рост, уже учтённый базой. Отдельно показываются модель и поправка.
- Исторический календарь: месяц, процент, дата публикации, источник, вид записи;
  версии одного месяца, CSV/JSON, редактирование и полное сохранение при пагинации.
- Календарные признаки в Rust: текущий месяц либо лаги 0–3; сравнение базы,
  календарной модели и датированной экспертной поправки.
- Дата информации `tariff_as_of` для текущего прогноза: объявления после последнего
  месяца ИПЦ можно использовать явно, не перенося их в исторические бэктесты.

- Последние доработки не меняли производственные данные `data/` и отправочную форму ОПР.

## Решения, которые нельзя потерять

**Календарная модель экспериментальная и по умолчанию выключена.**
На доступном пилоте она не улучшила прогноз; не включать её автоматически в основной ансамбль.

Календарный контракт:
`{schema_version:1, region_code, series_id, records:[{date, rate, known_at, source, kind, weight?, baseline?}]}`.
`date` — YYYY-MM-01, `known_at` — YYYY-MM-DD, `rate` — месячное изменение в процентах;
`kind`: actual/plan/assumption. Нули должны быть явными; пропуск не равен нулю.
Параметр `config.tariff_features`: off/current/lags3. Новые признаки доступны только для RAW.
При включении у Huber заменяется прежний фиксированный тарифный dummy, остальные сезонные
настройки сохраняются. Это не просто добавление ещё одного независимого признака к неизменной базе.

Обучение и прогноз используют версии календаря, известные к информационной дате.
Для текущего прогноза пустой `tariff_as_of` означает конец месяца отсечения; явная дата
может быть позднее и позволяет учесть новые объявления. В каждом бэктесте override сбрасывается:
берётся конец именно его исторического месяца. Будущие данные и пересмотры не должны влиять на результат.

При пропусках тарифной истории соответствующие строки обучения пропускаются; неизвестный будущий
месяц делает прогноз недоступным. Отсутствие календаря для текущего будущего пути не блокирует
исторические бэктесты. База может использовать больше обучающих наблюдений, чем календарная модель:
поэтому разницу MAE пока нельзя интерпретировать как чистый эффект новых признаков.

Ручная поправка: `weight * (rate - baseline) / 100` п.п. месячного ИПЦ.
Вес — доля в **общем** региональном ИПЦ, а не доля внутри услуг. `baseline` — экспертное предположение,
не автоматически оценённый моделью тарифный вклад. Нулевая база не гарантирует отсутствия двойного учёта.
Поправка не моделирует косвенный перенос издержек и не подаётся обратно в рекурсию модели.
Современная ручная таблица будущего сценария не применяется к бэктестам. Исторический экспертный
вариант требует собственных весов и предположений, сохранённых с датами доступности.

HAC/поправка Holm относятся к парной разнице ошибок прогнозов, а не к значимости коэффициентов
Ridge/Huber. При неполных/малых выборках p-values не выводятся. Не выбирать настройки на том же
тестовом окне, которое затем используется как доказательство преимущества.

## Текущий тарифный пилот и результат

Сохранены первичные PDF, исходные пределы, manifest с хешами и построитель
[build_cap_proxy.py](../portable/regional-inflation/data/tariffs/build_cap_proxy.py).
[Пилотный JSON](../portable/regional-inflation/data/tariffs/kbr_nalchik_monthly_payment_cap_proxy.json)
содержит 60 месяцев: **2018–2020 и 2025–2026**. 2016–2017 и 2021–2024 не заполнены.
Для остальных регионов подтверждённые календари в комплект пока не включены.

Это месячное изменение опубликованного предельного размера коммунальной платы **Нальчика**,
используемое как плановый индикатор для КБР. Это не фактическая тарифная инфляция всей республики.
Накопленные пределы преобразованы отношением уровней внутри года с декабрьской базой.
Например, 14,4% с октября 2026 — не месячный рост ИПЦ; при пределе 1,7% до октября
месячный индикатор изменения предела составляет около 12,487709%. Не подменять им пользовательскую
предпосылку «тарифы примерно +10%» или отправочный прогноз без отдельного экономического обоснования.
Дата доступности плана 2026 консервативно привязана к проверенной газетной публикации 20.12.2025.

Бэктест: цели сентябрь 2023 — август 2026, по 36 запланированных месяцев на горизонт.
На **одних и тех же валидных парах**, MAE в п.п.:

| Вариант | h | Пар | База | С календарём |
|---|---:|---:|---:|---:|
| Ridge, текущий месяц | 1 | 20 | 0,3895 | 0,4258 |
| Ridge, текущий месяц | 2 | 18 | 0,4590 | 0,6200 |
| Ridge, лаги 0–3 | 1 | 14 | 0,4240 | 0,4908 |
| Huber, текущий месяц | 1 | 13 | 0,3880 | 0,6089 |

На h=12 у Ridge/current одна пара, у остальных тарифных вариантов — ни одной.
Причины: пробелы истории, минимум обучения, отсутствие будущих расписаний на старых отсечениях,
а для Huber ещё и несходимость. Исторический экспертный вариант не оценён: нет проверенных
датированных весов и baseline. Его механика проверена на явно искусственном календаре.
Полные запросы, метрики и диагностики: [результаты эксперимента](../portable/regional-inflation/verification/tariff_calendar_evaluation.json).

## Что проверено и что не проверено

На текущем коде прошли 24 Rust-теста, 35 Node-тестов, 25 независимых проверок календарного ядра,
27 прежних браузерных проверок, 18 проверок ручного сценария, 21 проверка календарного интерфейса,
8 проверок реального пилота и 31 проверка локальных источников/ставок через PowerShell 7 Linux.
Проверены обмен файлами, пагинация, восстановление настроек, изоляция бэктестов,
дата информации, равенство native/WASM и отсутствие будущей информации.
Дополнительно прошли 7 проверок общего контракта и 26 проверок статистического сравнения.

Не трактовать ожидаемые частичные результаты как всеобщий успех:

- `verify_all_regions.py`: 393/404 успешных случая, 11 контролируемых ошибок сходимости Huber;
  новых неожиданных отказов нет. Скрипт возвращает exit code 1 при таком PARTIAL.
- `verify_reference.py --converged-reference`: 69/72; три недоступны из-за несходимости Huber SA
  Татарстана. Среди сходящихся расхождение Ridge <5e-12 п.п., Huber <0,000202 п.п.
- Windows физически не проверялся: проверены Chrome Linux и PowerShell 7 Linux.
- Полного real-time vintage бэктеста ИПЦ/макроданных, полной диагностики регрессоров и доказанной
  причинной интерпретации тарифных коэффициентов нет. Новая модель не продвигается.

```bash
rtk cargo test --manifest-path core/Cargo.toml
rtk cargo build --release --manifest-path core/Cargo.toml
rtk cargo build --target wasm32-unknown-unknown --release --lib --manifest-path core/Cargo.toml
rtk proxy wasm-bindgen --target no-modules --out-dir core/pkg --out-name regional_inflation_core core/target/wasm32-unknown-unknown/release/regional_inflation_core.wasm
rtk proxy node tools/build_html.mjs
rtk proxy python3 tools/verify_tariff_model.py
rtk proxy python3 tools/verify_tariff_calendar_browser.py
```

Перед выпуском выбирать проверки по изменённым путям, сохранять ограничения, сверять хеш HTML
в браузерных отчётах и пересобирать ZIP после обновления входящих файлов.
Исследовательские Python-скрипты — инструменты разработчика; пользователю приложения Python не нужен.
`/tmp/regional-pwsh/pwsh` использовался для проверки PowerShell, но это временный путь,
а не зависимость приложения и не гарантированная часть нового окружения.
