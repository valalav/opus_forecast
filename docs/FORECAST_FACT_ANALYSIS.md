# План-факт анализ прогноза ИПЦ

Этот документ описывает задачу подготовки объяснительного отчёта, когда
отправленный прогноз ИПЦ отличается от официального факта.

## Когда использовать

Используйте этот контур, когда нужно подготовить отчёт вида:

- какой прогноз был направлен;
- какой официальный факт вышел;
- насколько прогноз отклонился от факта;
- какие компоненты и товары объясняют отклонение;
- является ли месяц исторически обычным или аномальным;
- какие выводы учесть в следующем прогнозе.

Типовой результат — готовый `docx` для отправки и `xlsx` с расчётами.

## Входные данные

### Обязательные

| Данные               | Файл / источник             | Назначение                                     |
| -------------------- | --------------------------- | ---------------------------------------------- |
| Отправленный прогноз | значение от пользователя    | Плановое значение, например `100,45`           |
| Официальный факт     | `data/inflation_data.csv`   | Источник факта, компонентов и макроиндикаторов |
| Компонентные веса    | текущий рабочий набор весов | Вклад компонентов в MoM                        |

Для стандартного верхнеуровневого разложения используются веса:

| Компонент                  |      Вес |
| -------------------------- | -------: |
| Продовольственные товары   | `0.3986` |
| Непродовольственные товары | `0.3638` |
| Услуги                     | `0.2376` |

### Дополнительные

| Данные                      | Файл / источник                                    | Назначение                                |
| --------------------------- | -------------------------------------------------- | ----------------------------------------- |
| Исторические недельные цены | `data/kbr_weekly_prices_2008_2026.csv`             | История товарной сезонности               |
| Оперативные недельные цены  | `data/Сравнение еженедельных цен_01.csv`           | Внутримесячные драйверы и nowcast-сигналы |
| Расширенные веса            | `data/access_weights.csv`                          | Детальное разложение при необходимости    |
| Справочник товаров          | `data/items_names.csv`, `data/items_structure.csv` | Названия и структура товарных позиций     |

## Важное правило про факт и nowcast

Официальным фактом месяца считается только строка в
`data/inflation_data.csv`.

Недельные данные следующего месяца не являются месячным фактом. Например,
если в оперативном weekly-файле уже есть наблюдения начала мая, но в
`data/inflation_data.csv` нет строки за май, то в отчёте по апрелю их нельзя
называть фактом мая. Их можно упоминать только как предварительный
оперативный сигнал, если это явно нужно.

## Методика анализа

### 1. План-факт

Рассчитать:

```text
forecast_mom = forecast_index - 100
fact_mom = fact_index - 100
error_pp = forecast_mom - fact_mom
abs_error_pp = abs(error_pp)
kpi_pass = abs_error_pp <= 0.5
```

В отчёте указывать направление ошибки: прогноз завысил или занизил факт.

### 2. Компонентный вклад

Для каждого компонента:

```text
component_mom = component_index - 100
contribution_pp = component_mom * component_weight
```

Минимальный набор компонентов:

- `Prod` — продовольственные товары;
- `Nonprod` — непродовольственные товары;
- `Serv` — услуги.

Проверка: сумма компонентных вкладов должна быть близка к общему `mom - 100`.

### 3. Исторический контекст

Сравнивайте факт не со всем рядом сразу, а с тем же календарным месяцем в
прошлые годы.

Для целевого месяца рассчитайте:

- среднее;
- медиану;
- 10% усечённое среднее;
- стандартное отклонение;
- Q1, Q3, IQR;
- outlier fences: `Q1 - 1.5 * IQR`, `Q3 + 1.5 * IQR`;
- годы-outliers;
- среднее без outliers;
- robust z-score через медиану и MAD;
- исторический минимум/максимум;
- количество дефляционных наблюдений для этого месяца.

Также полезно показать сезонную карту: сколько раз дефляция возникала в
каждом календарном месяце.

### 4. Товарные драйверы

Для объяснения конкретных причин используйте товарные данные:

1. Сравните цены конца предыдущего месяца и конца целевого месяца.
2. Найдите товары с наибольшим отрицательным и положительным вкладом.
3. Для ключевых товаров покажите динамику за последние 6–12 месяцев.
4. Сравните изменение целевого месяца с исторической сезонностью этого товара.

Пример интерпретации:

- цена товара резко выросла в предыдущие месяцы;
- в целевом месяце началась коррекция;
- коррекция совпала с сезонным плодоовощным снижением;
- эффект усилился макрофоном, например укреплением рубля.

### 5. Макро- и сопутствующий фон

Из `data/inflation_data.csv` проверьте:

- `usd_nom_i` — валютный фон;
- `Ki_i`, `Ki` — ключевая ставка / индекс ставки;
- `Ruonia`, `Ruonia_i` — денежный рынок;
- `all_real` — реальный индикатор / спросовой фон;
- `fl_potrb_zad`, `fl_dep` — ожидания / депозитный фон.

Не утверждайте причинность, если данные показывают только сопутствующий фон.
Формулируйте аккуратно: “согласуется с”, “могло дополнительно давить”,
“усилило фон”.

## Типовая структура отчёта

1. **Резюме** — прогноз, факт, ошибка, главная причина.
2. **План-факт** — таблица прогноза, факта и KPI.
3. **Компонентный вклад** — проды, непроды, услуги.
4. **Исторический контекст** — метрики, outliers, сезонность дефляции.
5. **Товарные драйверы** — конкретные позиции и их вклад.
6. **Динамика ключевых товаров** — последние месяцы и сезонное сравнение.
7. **Макрофон** — рубль, ставки, реальные индикаторы.
8. **Аналогии с прошлым** — похожие периоды, например 2022 год.
9. **Выводы для следующего прогноза** — что учитывать в модели/экспертной
   корректировке.

## Пример

Готовый пример апрельского отчёта:

- DOCX: `archive/results/april_2026_deviation_analysis/april_2026_forecast_deviation_analysis.docx`
- XLSX: `archive/results/april_2026_deviation_analysis/april_2026_forecast_deviation_calculations.xlsx`
- Скрипт сборки: `archive/results/april_2026_deviation_analysis/build_april_deviation_report.py`
- Контрольный отчёт по отправочному пакету: `archive/results/full_forecast_package_2026_2027/verification_report.md`
- Контрольные скрипты: `archive/results/full_forecast_package_2026_2027/verification_scripts/`

В этом примере прогноз `100,45` сравнивается с фактом апреля 2026 `99,72`.
Отчёт показывает, что ошибка объясняется первым дефляционным апрелем в
доступной истории ряда, продовольственным отрицательным вкладом, ранней
плодоовощной коррекцией, коррекцией яиц после роста и укреплением рубля.

## Шаблон артефактов

Для нового месяца создавайте папку:

```text
archive/results/<month>_deviation_analysis/
```

Рекомендуемые файлы:

```text
<month>_forecast_deviation_analysis.docx
<month>_forecast_deviation_calculations.xlsx
build_<month>_deviation_report.py
```

В `xlsx` держите отдельные листы:

- `Summary`;
- `Component contributions`;
- `Robust history`;
- `Calendar month history`;
- `Monthly deflation seasonality`;
- `Product drivers`;
- `Key product summary`;
- `Key product dynamics`;
- `Comparable periods`;
- `Future template`.

## Контрольная проверка перед отправкой

Перед утверждением, что отчёт готов к отправке, сохраните явный след проверки:

1. Пересчитайте план-факт от официального `data/inflation_data.csv`.
2. Отдельно проверьте компонентные вклады и исторические метрики того же
   календарного месяца.
3. Отдельно проверьте товарные драйверы по weekly-файлу, не называя weekly
   данные следующего месяца официальным фактом.
4. Проверьте, что ZIP содержит ожидаемые DOCX/XLSX/CSV/MD-файлы.
5. Сохраните результат в `verification_report.md` рядом с отправочным пакетом.

Для апрельского пакета 2026 используются:

```bash
python3 archive/results/full_forecast_package_2026_2027/verification_scripts/verify_monthly_official.py
python3 archive/results/full_forecast_package_2026_2027/verification_scripts/verify_product_drivers.py
python3 archive/results/full_forecast_package_2026_2027/verification_scripts/verify_package_consistency.py
```

Ожидаемый итог проверки — пустые списки `mismatches` по всем трём блокам.
