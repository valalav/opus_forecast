# Находки из материалов Банка России и результат на локальных данных

## Зачем создан этот файл

Зафиксировать, какие идеи из материалов Банка России были проверены на текущем локальном датасете репозитория, что из этого реально дало улучшение, и как это связано с файлом основной статистики / `infostat`.

## Важное уточнение по данным ЮГУ

В рабочем дереве не был найден файл с явным названием вида `ЮГУ`, `YUGU`, `ЮФУ` или `основная статистика ЮГУ`.

Фактически в качестве наиболее вероятного соответствия использовалось семейство файлов:

- `data/raw/infostat.csv`
- `data/raw/infostat.xlsx`
- `data/infostat.csv`

Именно эти данные уже встроены в кодовую базу через:

- `sirena/macro_features.py`
- `load_production_proxies()`
- `add_production_features()`

То есть на практике работа велась не с отдельным явно подписанным файлом `ЮГУ`, а с тем локальным статистическим файлом, который в репозитории реально используется как источник прокси спроса и услуг.

## Что было извлечено из исследований Банка России

Из NotebookLM по корпусу материалов Банка России были извлечены несколько рабочих направлений:

1. short-term сигналы ожиданий и спроса важны для `h=1`;
2. асимметричный ERPT (перенос курса в цены) теоретически важен, особенно в волатильных режимах;
3. regime-aware / shock-aware спецификации имеют смысл после структурных сдвигов;
4. для локальной реализации нужно опираться только на те прокси, которые реально есть в репозитории.

Так как прямых данных по ожиданиям предприятий ЦБ локально нет, эти идеи были сведены к трем реализованным derivative-моделям на локальных данных.

## Какие доработки были реально реализованы

### 1. `RidgeProductionProxyForecaster` / `Ridge_ProdProxy`

Источник идеи из исследований ЦБ:

- добавление более чувствительных short-term индикаторов спроса / услуг;
- использование локальных прокси вместо отсутствующих survey expectations.

Локальная реализация:

- отдельный файл `sirena/models/ridge_production_proxy.py`;
- признаки из `infostat` через `add_production_features()`:
  - `torg_lag3`
  - `torg_lag6`
  - `torg_diff_lag3`
  - `torg_ma3`
  - `pp_lag3`
  - `pp_lag6`
  - `pp_diff_lag3`

### 2. `RidgeAsymmetricERPTProxyForecaster` / `Ridge_AsymERPT`

Источник идеи из исследований ЦБ:

- асимметричный pass-through курса;
- более сильное влияние depreciation-шоков и high-volatility regime.

Локальная реализация:

- отдельный файл `sirena/models/ridge_asymmetric_erpt_proxy.py`;
- proxy-features на основе `usd_nom_i`, `Ki`, `Ruonia`;
- разделение на depreciation / appreciation и regime interactions.

### 3. `RidgeShockRollingForecaster` / `Ridge_Shock_Roll24`

Источник идеи из исследований ЦБ:

- режимность и структурные сдвиги после 2022;
- необходимость более адаптивной сезонной нормы / rolling-подстройки.

Локальная реализация:

- отдельный файл `sirena/models/ridge_shock_rolling.py`;
- rolling seasonality + shock dummies в derivative-версии базовой ridge shock модели.

## Что дало результат

### Реально сработавшая доработка: `Ridge_ProdProxy`

После полного repo-level rerun и post-review fix-проверки модель показала:

- `h=1`: MAE `0.294`
- `h=2`: MAE `0.298`
- `h=12`: MAE `0.306`

Интерпретация:

- это лучший результат первой волны;
- гипотеза о полезности локальных demand/services proxies подтвердилась;
- именно эта линия является самым убедительным практическим результатом из идей, пришедших из материалов Банка России.

## Что не подтвердилось как улучшение

### `Ridge_AsymERPT`

Результаты:

- `h=1`: MAE `0.346`
- `h=2`: MAE `0.384`
- `h=12`: MAE `0.385`

Вывод:

- сама идея из исследований ЦБ содержательно разумна;
- но на текущем локальном наборе данных proxy-реализация не дала выигрыша;
- модель следует считать экспериментальной, не production-кандидатом.

### `Ridge_Shock_Roll24`

Результаты:

- `h=1`: MAE `0.317`
- `h=2`: MAE `0.355`
- `h=12`: MAE `0.347`

Вывод:

- модель рабочая и честно интегрирована;
- но она не стала лучшим вариантом;
- сейчас это полезный сравнительный derivative-вариант, а не главный кандидат на продвижение.

## Главный практический вывод

Если отвечать строго на вопрос «есть ли реальные доработки, которые дали результат из идей Банка России?», то ответ такой:

- **да, есть**;
- подтверждённый положительный результат дала линия **локальных прокси спроса/услуг**, реализованная как `RidgeProductionProxyForecaster`;
- в текущем репозитории эта линия опирается именно на `infostat`, который и выступает фактическим локальным аналогом “основной статистики” для этой задачи.
