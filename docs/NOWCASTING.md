# Nowcasting: методика использования недельных данных

## Обзор

**Nowcasting** — оперативная корректировка месячного прогноза инфляции на
основе недельных данных о ценах, публикуемых Росстатом.

Цель — получить диагностический сигнал по текущему месяцу до публикации
официального месячного ИПЦ и понять, какие товары или компоненты двигают
расхождение с модельным прогнозом.

## Источники данных

### Свежий semicolon-файл

**Оперативный путь:** `data/Сравнение еженедельных цен_01.csv`

```csv
Name;Наименование;Средние цены, рублей;Изменение цен, в % к предыдущей неделе;Компонент;№
12.01.2026;Говядина (кроме бескостного мяса), кг;649,55;101,28;Продовольственные товары;1
```

Оперативный файл используется для свежего weekly bridge nowcast, потому что
нормализованный исторический CSV может отставать от последних публикаций.
Loader находится в `sirena/data/weekly_bridge.py`.

### Исторический нормализованный CSV

**Путь:** `data/kbr_weekly_prices_2008_2026.csv`

Этот файл обслуживает исторические weekly-модели через
`sirena/data/weekly_loader.py`. Его нельзя считать автоматически свежим: перед
оперативным nowcast проверяйте последнюю дату в файле.

## Загрузка свежих недельных данных

Для row-wise semicolon-файла используйте готовый loader:

```python
from sirena.data.weekly_bridge import load_semicolon_weekly_prices

weekly = load_semicolon_weekly_prices()
```

Loader выполняет контрактные операции:

- принимает `Name` или `Date` как колонку даты;
- парсит русские десятичные запятые;
- классифицирует компоненты так, чтобы `Непродовольственные` не попадали в
  `Продовольственные`;
- дедуплицирует повторные блоки по `(date, item_key)`;
- сохраняет metadata `raw_rows`, `deduped_rows`, `duplicates_removed`.

## Расчёт недельного индекса

Компонентные веса КБР берутся из `sirena/data/weekly_loader.py`:

| Компонент | Вес |
|-----------|-----|
| Продовольственные товары | 39.48% |
| Непродовольственные товары | 36.53% |
| Услуги | 23.99% |

Внутри каждой недели weekly bridge усредняет индексы товаров по компоненту, а
затем агрегирует компоненты с этими весами. Индекс `100` означает отсутствие
недельного изменения.

## Weekly bridge diagnostics v1

Диагностический слой вызывается так:

```python
from sirena.data.weekly_bridge import compute_weekly_bridge_for_months

diagnostics = compute_weekly_bridge_for_months(["2026-04", "2026-05"])
```

В `data/precomputed_forecasts.json` он сохраняется отдельно от прогнозных
моделей:

```json
{
  "diagnostics": {
    "weekly_bridge": {
      "method": "weekly_bridge_v1",
      "by_month": {
        "2026-04": {
          "chain": {},
          "month_end": {},
          "first_next_week_vs_month_end": {}
        }
      }
    }
  }
}
```

### Что считается

1. **Cumulative weekly chain** — перемножает недельные индексы внутри месяца:
   `∏(weekly_i / 100) - 1`.
2. **Extrapolated signal** — если в месяце меньше четырёх недель, добавляет
   оставшиеся недели как средний недельный MoM × `decay_factor=0.6`.
3. **Month-end price-level bridge** — сравнивает абсолютные цены последней
   доступной недели месяца с предыдущей доступной неделей до начала месяца.
4. **First-next-week controls** — если уже есть первая неделя следующего месяца,
   показывает движение относительно конца месяца и предыдущего month-end.
5. **Top drivers** — показывает товары с максимальным снижением/ростом и грубую
   компонентную contribution-оценку.

### Роль в прогнозе

`weekly_bridge` — диагностика, а не production-модель. Он не добавляется в
`forecasts` как отдельная модель и не входит в weighted `Ensemble`.

`scripts/precompute_forecasts.py` использует weekly bridge только для очистки
вспомогательного `forecasts.Nowcast`: weekly signal смешивается со средним
модельным proxy по календарным весам.

| Недель в месяце | Вес weekly | Вес model proxy |
|-----------------|------------|-----------------|
| 1 | 60% | 40% |
| 2 | 70% | 30% |
| 3 | 80% | 20% |
| 4 | 90% | 10% |

Production `Ensemble` остаётся модельным weighted average и не включает
`Nowcast`, `Micro` или `weekly_bridge`.

## CLI-проверка

Для ручной диагностики месяца:

```bash
python3 scripts/weekly_bridge_nowcast.py --month 2026-04
python3 scripts/weekly_bridge_nowcast.py --month 2026-04 --json
```

Для апреля 2026 этот CLI воспроизводит независимый weekly bridge без
использования инсайдерского `99,7` или старого значения `forecasts.Nowcast`.

## Ограничения

1. **Выборка товаров** — недельные данные покрывают около 100-200 товаров из
   более широкой месячной корзины ИПЦ.
2. **Задержка данных** — публикация недельных данных приходит с лагом.
3. **Методологический разрыв** — недельная публикация Росстата не является
   официальным месячным ИПЦ; последнюю неделю месяца нельзя считать
   официальным фактом без проверки на опубликованный месячный индекс.
4. **Волатильность плодоовощей** — отдельные товары могут сильно двигать
   недельный сигнал, но не полностью объяснять месячный ИПЦ.
5. **Компонентные средние** — current bridge использует простое среднее внутри
   компонента, а не полные официальные микровеса месячной корзины.

## Рекомендации

1. Обновлять fresh semicolon-файл каждую неделю и запускать CLI по текущему
   месяцу.
2. Сравнивать `chain` и `month_end`: расхождение между ними показывает, что
   недельные WoW-индексы и абсолютные price-level дают разные сигналы.
3. Смотреть top drivers до интерпретации общего сигнала.
4. Не включать weekly bridge в production `Ensemble`, пока не накоплен
   backtest на свежем формате и официальных месячных фактах.
5. После публикации факта делать decomposition miss: model forecast vs
   `Nowcast` vs `weekly_bridge.chain` vs `weekly_bridge.month_end`.
