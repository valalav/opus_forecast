# Сравнительный анализ планов реализации модели ЛММР

**Дата:** 18.12.2025
**Участники:** Gemini, Claude, Qwen

## 1. Обзор подходов

| Характеристика | Gemini | Claude | Qwen |
|----------------|--------|--------|------|
| **Основная идея** | Адаптация под *доступные* данные + практичность (избегание X13 в проде). | Строгое следование архитектуре R-кода, STL декомпозиция, подробная интеграция. | Теоретический упор на "Mixed Models" (LNM), использование случайных эффектов, сложная архитектура. |
| **Интерпретация "ЛММР"** | Линейная Многофакторная Модель Регрессии (Dynamic Regression on SA data). | Локальная Мультипликативная Модель Регрессии (Dynamic Regression on SA data). | Линейная Смешанная Модель (Linear Mixed Model - Random/Fixed Effects). |
| **Сезонность** | `seasonal_decompose` + Naive/ETS (простота). | `STL` (Robust Seasonal-Trend decomposition using Loess). | `statsmodels.MixedLM` + внешние вызовы R/JDemetra (сложно). |
| **Базовая модель** | `ElasticNet` / `LinearRegression` (sklearn). | `Ridge` (sklearn) с `RobustScaler`. | `statsmodels.mixed_linear_model.MixedLM`. |
| **Работа с данными** | Акцент на замене отсутствующих факторов (RealIncome, Credit). | Использование Brent как прокси для PPI/Freight. Явные shock dummies. | Использование иерархических данных (компоненты как случайные эффекты). |

## 2. Детальное сравнение

### 2.1 Gemini: "Прагматичный подход"
*   **Сильные стороны:**
    *   Реалистичная оценка доступности данных (замена PPI/Freight на Доходы/Кредиты).
    *   Простое решение проблемы X13 (Naive/ETS для сезонности), что критично для production без Java-зависимостей.
    *   Фокус на интеграции с существующим `USDForecaster`.
*   **Слабые стороны:**
    *   Менее детально прописан код самого класса модели по сравнению с Claude.
    *   Меньше внимания уделено точной репликации логики R-скрипта (базисные индексы).

### 2.2 Claude: "Архитектурный подход"
*   **Сильные стороны:**
    *   **Лучшая техническая детализация:** Готовый код для `_to_base_index`, `STL`, `backtest`.
    *   **Правильный выбор STL:** Это современная, робастная альтернатива X13, доступная в Python (`statsmodels`).
    *   **Четкая структура:** Полный цикл от `__init__` до интеграции в Dashboard и тесты.
    *   **Shock Dummies:** Явно прописаны все шоковые переменные из методики ЦБ.
*   **Слабые стороны:**
    *   Использование Brent как прокси для цен производителей (PPI) может быть менее точным, чем реальные данные, но это вынужденная мера.

### 2.3 Qwen: "Теоретический подход"
*   **Сильные стороны:**
    *   Глубокое понимание эконометрики (Mixed Effects).
    *   Предложение использовать иерархическую структуру данных.
*   **Слабые стороны:**
    *   **Вероятная ошибка интерпретации:** Qwen расшифровал ЛММР как "Mixed Models" (смешанные эффекты), хотя в R-коде используется `dynlm` (обычная динамическая регрессия). Mixed Models здесь — излишнее усложнение.
    *   **Сложность реализации:** Предлагает вызывать R через `rpy2` для сезонности, что создаст ад в поддержке (dependency hell).

## 3. Синтез (Unified Plan)

Для реализации мы возьмем лучшее из всех планов, отдавая предпочтение архитектуре Claude, но с учетом прагматичных правок Gemini по данным.

**Итоговая стратегия:**

1.  **Архитектура (от Claude):**
    *   Использовать структуру класса `LMMRForecaster`.
    *   Использовать `STL` (из `statsmodels`) вместо X13 или простой декомпозиции. Это "золотая середина" по качеству и простоте.
    *   Реализовать преобразование MoM -> Base -> STL -> Base -> MoM.

2.  **Данные (Синтез Gemini + Claude):**
    *   **Таргет:** SA ряд (через STL).
    *   **Факторы:**
        *   Лаг таргета (AR component).
        *   `usd_nom_i` (лаг 1) — есть в данных.
        *   `brent` (лаг 1, 3) — как прокси внешних цен (предложение Claude).
        *   `all_real` (Реальные доходы) или `fl_potrb_zad` (Кредиты) — как прокси спроса (предложение Gemini). *Решение: протестировать оба, выбрать лучший по AIC.*
    *   **Shock Dummies:** Взять полный список из плана Claude (2014, 2015, 2022).

3.  **Модель (от Claude/Gemini):**
    *   `Ridge` или `ElasticNet` (sklearn). `Ridge` предпочтительнее для коллинеарных факторов (USD и Brent часто коррелируют).

4.  **Сезонность (от Claude):**
    *   Прогнозировать сезонную компоненту `seasonal` из STL наивным методом (прошлогоднее значение) или простым средним, так как STL дает стабильную сезонность.

## 4. План действий

1.  Создать `sirena/models/lmmr.py` на основе кода Claude (он наиболее полон).
2.  Добавить в него логику выбора факторов: помимо Brent/USD добавить `all_real` (Доходы) из плана Gemini, так как это важный фактор спроса.
3.  Написать тесты и интегрировать в реестр моделей.
4.  Сравнить на бэктесте с текущим Ridge.

**Победитель:** План **Claude** является наиболее проработанным и технически верным (особенно выбор STL). План **Gemini** полезен уточнением по доступным данным (факторы спроса). План **Qwen** слишком усложнен и, вероятно, неверно интерпретировал тип модели.
