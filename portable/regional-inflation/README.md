# Региональная инфляция — переносимое приложение

## Запуск и локальные файлы

Распакуйте `regional-inflation.zip` в отдельную папку. На Windows запустите **Start.cmd**: он открывает приложение в браузере и запускает локальный PowerShell-сервер на 127.0.0.1. Python, Node и установленный Rust не нужны. Сервер использует TcpListener и не регистрирует системные URL; права администратора для такой регистрации не требуются. Windows отдельно ещё не проверена; реальный сервер проверен в PowerShell 7 на Linux.

По умолчанию приложение ищет статистику **в папке рядом с HTML**. ZIP содержит стартовые `regional_indices.json` и `macro_rates.json`. Положите туда более свежий региональный XLSX, и загрузчик выберет его вместо JSON. Поле локального пути позволяет указать другую папку. Поиск локальной статистики, обновление ИПЦ с Яндекса и загрузка ставок ЦБ — отдельные действия.

Можно открыть `regional-inflation.html` непосредственно, без сервера и интернета. В этом режиме работают встроенные данные, прогноз, бэктест и импорт файлов. Произвольный путь браузер сам читать не может: используйте выбор папки или файлов. Для прямого сетевого скачивания ставок ЦБ используйте Start.cmd; браузер может блокировать прямой запрос к ЦБ из автономной страницы.

## Данные и ставки ЦБ

Региональный выпуск: август 2026, 101 территория (85 субъектов, Россия и округа), преимущественно с января 2016. [Источник Яндекс.Диска](https://disk.yandex.ru/d/i6czrcdNO0I7BQ). В `2026-08 ИПЦ с исключением сезонности (регионы).xlsx` лист `db` содержит одновременно RAW `mom` и SA `mom_sa`, по общему ИПЦ, продуктам, непродовольственным товарам и услугам. RAW и SA не смешиваются.

В книге «ИПЦ полный» региональные данные находятся во внутренней модели Excel. Приложение пока не декодирует её бинарный формат; используется плоский лист регионального SA-файла. Если выбран только неподдерживаемый файл, показывается объяснение.

**Ki и RUONIA больше не привязаны к проектному CSV.** В макроблоке:

1. Задайте период и способ перевода дневных ставок в месячные.
2. Нажмите «Скачать с Банка России». Используются официальные операции [KeyRateXML](https://www.cbr.ru/DailyInfoWebServ/DailyInfo.asmx?op=KeyRateXML) и [RuoniaXML](https://www.cbr.ru/DailyInfoWebServ/DailyInfo.asmx?op=RuoniaXML).
3. Сохраните отдельный JSON ставок. Без интернета импортируйте этот файл и пересчитайте прогноз.

Поддерживаются JSON-пакет приложения, пара официальных XML и CSV с колонками Date/Ki/Ruonia, как в основном проекте. XLSX с сайта ЦБ пока не поддерживается. В локальной папке `macro_rates.json` имеет приоритет над `inflation_data.csv`.

Начальный набор ставок перепроверен по официальным XML за январь 2016 — август 2026. По умолчанию Ki — последнее опубликованное значение месяца, RUONIA — арифметическое среднее опубликованных дневных наблюдений. Для каждого ряда можно выбрать последнее значение или среднее. Это среднее по опубликованным наблюдениям, не календарно-взвешенная ставка. Незавершённый текущий месяц не выдаётся за полный.

Сохранённый JSON хранит ряды, способ агрегирования, даты и происхождение. Для пакета с дневными данными сохраняются и дневные наблюдения. Импорт JSON воспроизводит сохранённую агрегацию; выбранные в форме методы применяются при новой загрузке ЦБ или импорте XML. Отсутствующие месяцы не заменяются старыми ставками или нулями: при включённых макрофакторах нужна полная история ставок на выбранном периоде обучения. Можно сократить период обучения или явно выключить макрофакторы.

В предыдущем наборе ставки были скопированы из `data/inflation_data.csv`. Найдено расхождение: сентябрь 2023, Ki=15 вместо последнего официального значения 13. Исходный CSV основного проекта не изменён; официальный набор используется в переносимом приложении. Поэтому его результаты могут отличаться от первой версии.

## Что прогнозируется

Выберите регион, RAW/SA, Ridge/Huber и горизонт. Модель прогнозирует **только общий месячный ИПЦ**. Продукты, непродовольственные товары, услуги, Ki и RUONIA используются в признаках; в будущем они фиксируются на последнем доступном значении. Отдельного прогноза этих переменных или автоматического сценария ставок здесь нет.

Входные месячные индексы около 100 преобразуются для показа в MoM: `I - 100`. Рядом приводится годовая инфляция RAW: `100 × (произведение 12 индексов I/100 − 1)`. В прогнозе произведение включает только факты до отсечения и прогнозные месяцы. В таблице бэктеста годовая колонка — фактический годовой темп; метрики относятся к MoM. Для SA официальный годовой темп не показывается.

## Настройки, выбросы и проверка

Параметры обучения, alpha, epsilon, итерации, допуск, макрофакторы, исключаемые годы, горизонт и отсечение редактируются. Настройки можно сохранить/загрузить JSON.

Сезонность:

- `legacy`: исходные календарные признаки и смешивание с месячной сезонной нормой; 12 весов смешивания редактируются.
- `features_only`: те же признаки без финального смешивания.
- `off`: календарные признаки, сезонная норма и отклонение от неё удаляются, смешивание отключается. Авторегрессионные лаги, включая лаг 12, остаются.

Автоматическая обработка выбросов `mad_winsor`: внутри каждой обучающей выборки оценивается медиана по календарным месяцам для RAW, общая медиана для SA; остатки ограничиваются порогом `threshold × 1,4826 × MAD`. Меняется только целевая переменная при обучении, не исходные данные и не факты проверки. Видны количество и даты обработанных наблюдений. При нулевом MAD ограничение не применяется. Порог редактируется. Исключаемые годы действуют в обоих сравниваемых вариантах; стандартный Ridge уже исключает 2022 из регрессии.

Скользящая проверка использует общие целевые месяцы и h=1/2/12. Показываются MAE, RMSE, смещение, попадание в ±0,5 п.п. и доступные/запланированные наблюдения. Пропуски остаются пропусками.

Кнопка сравнения запускает **без автоматического ограничения / с ограничением** на одинаковом окне. Положительная разница MAE означает меньшую ошибку второго варианта. Значимость оценивается по парным разностям абсолютных ошибок: Newey–West HAC с ядром Bartlett, приближённый нормальный 95%-ный интервал и p-value; поправка Holm учитывает горизонты. При коротком окне, пропусках или нулевой дисперсии p-value не рассчитывается. Это исследовательское сравнение, не доказательство качества настроек, подобранных по этому же окну. p-value коэффициентов Ridge/Huber не выдаются.

Тарифный календарь `{"2026":10,"2027":7}` меняет календарный признак Huber в прогнозе. Это не величина индексации и не количественная оценка её вклада в ИПЦ. Историческая проверка сохраняет июльский признак; будущие экспертные предположения в прошлое не переносятся.

Huber использует другой численный оптимизатор, чем исходная Python-модель. Одинаковая функция потерь проверяется независимым эталоном. Возможна несходимость: она отображается как ошибка. Центрирование целевой переменной внутри оптимизатора уменьшает численные проблемы, не меняя задачу. Нельзя автоматически считать Huber точнее Ridge.

## Проверка и сборка

[Текущий отчёт v2](verification/REPORT_V2.md) описывает точный объём проверок и ограничения. SA — пересмотренная история, поэтому её бэктест не является настоящим real-time тестом на исторических публикациях. Модели не продвигаются автоматически в производственный прогноз СИРЕНА-КБР.

Разработчику нужны Rust + wasm32-unknown-unknown, wasm-bindgen-cli 0.2.129 и Node.js. В каталоге приложения:

```sh
npm ci
cargo build --manifest-path core/Cargo.toml --release
cargo build --manifest-path core/Cargo.toml --target wasm32-unknown-unknown --release --lib
wasm-bindgen --target no-modules --out-dir core/pkg --out-name regional_inflation_core core/target/wasm32-unknown-unknown/release/regional_inflation_core.wasm
npm run build:html
node --test tests/*.test.mjs
```

Python используется только разработчиком для независимых проверок в `tools/`. `verify_browser_v2.py --pwsh /path/to/pwsh` проверяет реальный сервер и цикл загрузки ставок. Нативный Rust CLI также собирается из `core/`; Windows EXE в комплект не входит.

## Тарифные месяцы и проценты

Откройте «Сценарий тарифов: месяцы и проценты», добавьте строки и включите сценарий.
Для каждой строки укажите месяц, индексацию, предполагаемый рост, уже учтённый базой модели,
и вес затрагиваемых тарифов **в общем ИПЦ выбранного региона** (не внутри услуг).
Все значения задаются пользователем; встроенных оценок веса или базового тарифного роста нет.
Сценарий по умолчанию выключен. Пустые обязательные поля вызывают ошибку.

Прямая приближённая поправка к месячному ИПЦ, п.п. = вес, % × (индексация − учтённый рост), % / 100.
Пример: 10% индексации при весе 5% и базе 0% добавляет 0,5 п.п.; это условный пример, не оценка веса ЖКУ.
Если в базе уже учтены 10%, такая же индексация даёт нулевую поправку.
Для переноса с июля на октябрь задайте отмену в июле (сценарий 0%, база 10%) и повышение в октябре
(сценарий 10%, база 0%), при одинаковом весе. Оба месяца должны входить в прогнозный горизонт.
Для прогноза из августа прошедший июль менять нельзя: он уже является фактом.

Базовая модель сама не выделяет тарифный вклад. Поле «Уже учтено» — экспертное предположение,
которое необходимо согласовать с сезонностью и отдельной настройкой тарифного месяца Huber.
Нулевая база не гарантирует отсутствия двойного учёта. Если задаёте несколько событий в месяце,
их веса должны относиться к непересекающимся частям корзины; сумма не должна превышать 100%.
Вес для каждого месяца можно менять. Это приближённая декомпозиция, а не полный индекс Ласпейреса.

Таблица и CSV показывают модель, поправку и сценарий, месячные и составные годовые темпы.
График показывает сценарий; база сохранена в таблице и JSON (`model_forecast`).
События сохраняются в настройках JSON и отчёте расчёта. RAW-сценарий не применяется к SA и бэктестам.
Поправка не подаётся обратно в рекурсию модели и не оценивает косвенный перенос издержек.
Проверки и ограничения: [отчёт тарифного сценария](verification/TARIFF_SCENARIO.md).
