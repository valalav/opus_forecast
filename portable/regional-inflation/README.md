# Региональный прогноз инфляции

Откройте `regional-inflation.html` в современном Chrome или Edge. Файл можно скопировать коллегам: установка Python, Rust и сервера не нужна. Расчёт выполняется локально через Rust/WebAssembly; встроенные данные доступны без интернета.

## Использование

1. Выберите регион, RAW или SA, Ridge или Huber.
2. Выберите прогноз либо историческую проверку. В дополнительных параметрах доступны горизонт, начало обучения, отсечение данных, регуляризация, параметры оптимизации, макрофакторы, сезонные веса, исключаемые годы и тарифный календарь.
3. Запустите расчёт. Историческая проверка показывает MAE, RMSE, смещение и долю ошибок в пределах 0,5 п.п. отдельно для h=1, h=2 и h=12. Число доступных наблюдений показывается вместе с запланированным.
4. Сохраните CSV или полный расчёт JSON с параметрами и источником. Для обновления используйте кнопку Яндекс.Диска либо импорт локального XLSX/JSON. После обновления сохраните пакет JSON для переноса на другой компьютер; исходный HTML автоматически не перезаписывается.

## Данные и ограничения

Встроен выпуск августа 2026 года: 101 территориальный ряд, включая 85 субъектов, Россию и округа. Основная история начинается в январе 2016 года; фактическое покрытие показывается для выбранной территории.

Источник: [публичная папка ИПЦ](https://disk.yandex.ru/d/i6czrcdNO0I7BQ), файл `2026-08 ИПЦ с исключением сезонности (регионы).xlsx`. Лист `db` содержит **оба** столбца: `mom` для RAW и `mom_sa` для SA. Четыре агрегата: общий ИПЦ, продукты, непродовольственные товары и услуги. Входные значения — индексы около 100; прогноз и ошибки — проценты и процентные пункты. RAW и SA не смешиваются. История SA пересмотренная: backtest не является проверкой на подлинных исторических винтажах публикаций.

В `ИПЦ полный.xlsx` региональные данные находятся во внутренней модели Excel. Этот бинарный формат прототип не декодирует; наличие региональных данных в нём не отрицается. Для автоматического обновления используется плоская таблица регионального SA-файла. SHA-256 и сведения о выпуске сохраняются в пакете.

Ключевая ставка и RUONIA — общероссийские ряды из `data/inflation_data.csv` основного проекта. Обновление регионального XLSX **не обновляет ставки**. Если обязательные макроданные отсутствуют, расчёт завершается видимой ошибкой; можно явно выключить макрофакторы или импортировать актуальный JSON-пакет. Будущие компоненты и ставки фиксируются на последнем доступном значении; рекурсивно прогнозируется общий ИПЦ. Это условная модельная траектория.

Тарифный календарь задаётся JSON, например `{"2026":10,"2027":7}`. Он меняет календарный признак Huber в прогнозе, но не задаёт величину индексации или экспертную прибавку к ИПЦ. В исторической проверке сохранён июльский признак исходной модели: будущие экспертные предположения в прошлые отсечения не переносятся. Для экономической оценки эффекта 10%-ной индексации нужны веса и отдельный сценарий.

Ridge воспроизводит исходные формулы. Huber решает ту же задачу с совместной оценкой масштаба ошибки, но использует другой численный оптимизатор. Исходный Python Huber на ряде проверенных выборок достигает лимита 500 итераций; поэтому точного совпадения с его незавершённым решением нет. Совпадение проверено с высокоточным решением той же задачи. Это не доказательство улучшения прогнозной точности: оценивайте метрики выбранного региона. Настройки по умолчанию не оптимизированы под каждый субъект. В проверке нативного ядра Ridge рассчитался для всех территорий; Huber при стандартных 500 итерациях не сошёлся в 27 из 202 сочетаний территории и RAW/SA. В таком случае интерфейс сообщает об ошибке, а не выдаёт незавершённый расчёт как прогноз. Увеличение лимита до 10 000 не помогло этим 27 случаям; допуск `1e-4` вместо `1e-5` позволил принять 26 из них. Это изменение критерия сходимости, а не доказанное улучшение прогноза. Для надёжного первого запуска используйте Ridge.

## Сборка для разработчика

Требуются Rust с целью `wasm32-unknown-unknown`, `wasm-bindgen-cli` версии 0.2.129 и Node.js. В каталоге проекта:

```sh
npm ci
cargo build --manifest-path core/Cargo.toml --release
cargo build --manifest-path core/Cargo.toml --target wasm32-unknown-unknown --release --lib
wasm-bindgen --target no-modules --out-dir core/pkg --out-name regional_inflation_core core/target/wasm32-unknown-unknown/release/regional_inflation_core.wasm
npm run build:html
```

`core/` также собирается в нативный CLI, принимающий JSON через stdin. Это основа для будущего Windows EXE; готовый Windows EXE в этом выпуске не поставляется.

Python нужен только разработчику для подготовки и независимой проверки. Скрипты находятся в `tools/`, результаты — в `verification/`. Браузерная проверка выполнялась в Chrome на Linux, включая `file://` и отключённую сеть. Запуск на физической Windows отдельно не проверен.

Проверки из корня основного репозитория:

```sh
cargo test --manifest-path portable/regional-inflation/core/Cargo.toml
python3 -m pytest portable/regional-inflation/tests/test_prepare_data.py -q
python3 portable/regional-inflation/tools/verify_reference.py --converged-reference
python3 portable/regional-inflation/tools/verify_kernel_contract.py
python3 portable/regional-inflation/tools/verify_all_regions.py
python3 portable/regional-inflation/tools/verify_browser.py
python3 portable/regional-inflation/tools/verify_yandex_browser.py
python3 portable/regional-inflation/tools/verify_source_browser.py /path/to/regional_sa.xlsx
```

Последняя проверка сравнивает исходную книгу именно со встроенным выпуском августа 2026. `verify_reference.py` без флага высокоточного эталона намеренно выявляет расхождение с незавершённым старым Huber и возвращает ненулевой код. Зависимости эталона — Python-пакеты основного проекта; браузерных тестов — Playwright и Chrome.
