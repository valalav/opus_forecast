# Проверка переносимого регионального приложения — 2026-09-28

Экспериментальное приложение находится отдельно от производственных моделей. Интерфейс, подготовку данных и Rust-ядро реализовали Luna; итоговые методические решения, независимое сравнение и браузерную проверку выполнил основной агент.

## Источник

Проверена публичная папка Яндекс.Диска. В региональном SA XLSX выпуска 2026-08 лист `db` содержит RAW `mom` и SA `mom_sa`. Браузерный парсер совпал с независимым Python-экспортом по 155 040 числовым значениям для 101 территории. SHA-256 книги: `1a3648b2de7f3b777e20e5912da576acbcc0e9a5d827a89eefe290c01bbea84f`. Загрузка из Яндекса проверена из локального `file://` Chrome; около 5 секунд через кнопку обновления готового HTML. Источники и ограничения макрорядов описаны в README и `data/source_audit.json`.

## Численная и поведенческая проверка

- 8 Rust unit tests и 2 теста подготовки данных прошли.
- 72 сравнения с высокоточным независимым эталоном: три региона, RAW/SA, два отсечения, h=1/2/12. Все прошли; максимальное расхождение Ridge — 4,94e-12 п.п., Huber — 0,000264 п.п. Допуск Huber — 0,001 п.п.
- Семь контрактных проверок прошли: в том числе недоступные цели, расчёт метрик и инвариантность к изменениям будущих CPI/макронаблюдений. Все девять запланированных слотов сохранены: семь валидных, два недоступных. Недоступные наблюдения не подменены нулями.
- Проверены 404 полные двенадцатимесячные траектории: 101 территория × RAW/SA × Ridge/Huber. Ridge успешен 202/202. Huber со стандартным лимитом 500 итераций успешен 175/202; 27 случаев возвращают явную ошибку несходимости. Нет аварий процесса или некорректного JSON. Это **не** 404 успешных прогноза.

Чувствительность Huber: при `tol=1e-5` увеличение лимита до 2 000 и 10 000 не изменило функцию потерь или градиент 27 проблемных оценок. При `tol=1e-4` сошлись 26 из них; Свердловская область RAW осталась с градиентом 0,00013035. Это остановка оптимизатора при проверенных настройках, не установленный предел машинной точности. Стандартные параметры сохранены; подробности в `huber_convergence_sensitivity.json`.

## Расхождение со старым Huber

`reference_parity.json` намеренно сохраняет отрицательный результат буквального сравнения с исходным Python: 36 Ridge-проверок проходят, 36 Huber-проверок не проходят. Максимальное расхождение траектории — около 2,025 п.п. на Татарстане. Проверенный Python Huber достигает лимита 500 итераций.

Например, КБР RAW по август 2026: значение функции потерь Python 81,91598, максимальная компонента градиента 28,49; Rust получает меньшую функцию потерь около 81,63683 и градиент порядка 5,5e-6. Высокоточный SciPy-эталон той же задачи подтверждает Rust. Нельзя выдавать Rust Huber за побитовый перенос старого незавершённого решения или объявлять улучшение прогнозной точности без backtest.

## Браузерная приёмка

Пройдены 27 браузерных проверок. Готовый HTML проверяется через `file://` при отключённой сети: выбор региона, RAW/SA, расчёт Ridge/Huber, совпадение WASM и нативного Ridge, содержимое таблицы и CSV, полный JSON расчёта, скользящие проверки h=1/2/12, сброс результата после изменения параметров, сохранение/импорт настроек, видимая ошибка некорректного JSON, адаптация к ширине 390 пикселей. Отдельный тест нажимает кнопку обновления Яндекса и сохраняет реально загруженный пакет.

График проверяется отдельно от ядра: исторические прогнозы накладываются на факты по общей оси дат; прогноз г/г равен произведению 12 месячных индексов; история на графике обрезается по выбранному отсечению. Для backtest отображается месячный темп. Точные результаты и хеш проверенного HTML находятся в `browser_ui.json` и `browser_yandex.json`.

## Область применимости

Исторические проверки используют текущую версию рядов, особенно пересмотренную SA; это не настоящие real-time винтажи. Тарифный календарь — календарный признак, не количественная модель переноса индексации в ИПЦ. Будущие компоненты и ставки фиксируются на последних значениях. Региональные настройки по умолчанию не подбирались по лучшим результатам на тесте.

Chrome на Linux проверяется локально; физическая Windows и нативный Windows EXE в этот выпуск проверки не входят. Приложение не меняет действующую отправочную траекторию ОПР и не заменяет производственный прогноз автоматически.
